# Codebase audit — 2026-08-20 (findings + implementation specs)

A timeboxed four-track audit (correctness, cross-package consistency, developer experience,
test coverage) of the whole workspace. **This document is a work order**: each item below is a
verified finding with a fix specced precisely enough to implement without re-investigation.
Items are grouped into three priority tiers and sized so one workstream ≈ one focused PR.

## Baseline at audit time (commit `9f9b826`)

- `ruff check .` — clean. `mypy` — clean (125 source files). All 724 tests pass (2 skips — see T1).
- `python -m tests.conformance_runner` — fully green.
- Coverage 94% overall. Weakest modules: `benzene-grpc/__init__.py` 53%, `benzene-azure/clients.py` 71%,
  `benzene-azure/app.py` 72%, `benzene-mesh-fleet/discovery_adapters.py` 73%, `benzene-mesh/probe.py` 78%,
  `benzene-codegen-client/types.py` 81%, `benzene-auth/bearer.py` 84%, `benzene-resilience/bulkhead.py` 85%.

## Ground rules for every workstream

1. **Write the failing test first.** Every behavioral claim below was verified by reading the code,
   but the test both re-proves the defect and pins the fix. If the failing test cannot be made to
   fail, stop and flag the item instead of "fixing" it.
2. **The gates must stay green after every workstream**: `ruff check .`, `mypy`,
   `pytest -q` (all of tests/ + examples/), and `python -m tests.conformance_runner`.
3. **The wire contract is frozen.** None of these items may change the envelope, status vocabulary,
   status↔HTTP/gRPC mappings, descriptor/collector semantics, or contract hashes. Items marked
   ⚠️ touch wire-adjacent code — re-run the conformance runner explicitly and say so in the PR.
4. Public API additions need docstrings; renames keep the old name as a working alias (this is
   pre-1.0, but the examples/docs/templates reference current names — update them in the same PR).
5. Match the house style: dataclasses, Protocols, injectable clocks/clients, duck-typed fakes,
   no new required third-party deps.

# P0 — Correctness (behavioral bugs, fix first)

## C1. Kafka consumer: committing a later record silently drops earlier failed records — **critical**

`packages/benzene-kafka/benzene/kafka/consumer.py` (`run_consumer_loop`, ~122–133).

The loop skips committing a failed record but keeps polling. Kafka commits are watermarks, not
per-message acks: when a later record on the *same partition* succeeds,
`consumer.commit(message=message)` commits that record's offset+1, which also marks every earlier
record — including the failed one — consumed. Sequence: offset 5 fails → no commit; offset 6
succeeds → committed offset becomes 7 → offset 5 is never redelivered. This contradicts the
docstring's at-least-once promise ("a failed record is redelivered rather than silently dropped").

**Fix** (minimal, keeps at-least-once honest): on a failed result, stop advancing past the failure —
`consumer.seek()` back to the failed record's `(topic, partition, offset)` and continue the loop
(so the record is re-fetched; existing `should_continue`/`on_result` seams let callers break out or
route to a DLQ). Never commit an offset beyond an uncommitted failure. Update the docstring to
describe the seek-back behavior and the poison-record consequence (the loop re-serves the failed
record; callers use `on_result`/`should_continue` to cap retries or dead-letter).

**Tests** (`tests/test_kafka.py`): fake consumer serving two records on one partition where record 1
fails and record 2 succeeds → assert `commit` is never called with record 2's offset and `seek` was
called back to record 1; and a record that fails then succeeds on redelivery → assert both commits
happen in order.

## C2. Kafka producer: flush timeout ignored — success reported for unacknowledged messages — **high**

`packages/benzene-kafka/benzene/kafka/producer.py` (`KafkaMessageSender.send_message`/`_publish`, ~73–88).

`producer.flush(self._flush_timeout)` returns the count of messages still un-acknowledged and the
return value is discarded. Broker unreachable → `produce()` buffers locally, `flush` times out
returning 1, no delivery callback fires, `delivery_errors` stays empty → `Result.ok()` for a message
that was never delivered.

**Fix**: capture `remaining = producer.flush(...)` in `_publish` and return it; in `send_message`,
if `remaining > 0` (or no delivery callback fired), return
`Result.failure(Status.TIMEOUT, "broker did not acknowledge within flush_timeout")`.

**Tests** (`tests/test_kafka.py`): fake producer whose `flush` returns 1 and never invokes
`on_delivery` → timeout failure; `flush` returns 0 + callback fired cleanly → ok.

## C3. Circuit breaker hardening: cancellation wedge + stale-outcome transitions — **high**

`packages/benzene-resilience/benzene/resilience/circuit_breaker.py` (`execute` ~103–135,
`_on_success`/`_on_failure` ~143–146).

Three defects in one module, one PR:

- **(a) Permanent lockout on cancelled probe.** `_admit` sets `_probing = True` for the half-open
  probe; only `_on_success`/`_on_failure` clear it, and `execute` catches only `Exception`.
  `asyncio.CancelledError` (a `BaseException`) propagates without recording → `_probing` stays True
  in HALF_OPEN forever → every subsequent `_admit` returns False. The breaker rejects 100% of
  traffic until process restart.
  **Fix**: in `execute`, add a `finally` (or `except BaseException: record-and-reraise`) so an
  admitted probe that ends without a recorded outcome resets `_probing = False` and returns the
  breaker to OPEN.
- **(b) Stale success instantly closes a tripped breaker.** `_on_success` sets `_state = CLOSED`
  unconditionally: with threshold 3, four concurrent calls admitted while CLOSED, three fail
  (breaker trips OPEN), the in-flight fourth then succeeds and erases the open window.
  **Fix**: in `_on_success`, transition to CLOSED only from HALF_OPEN (the probe) or when already
  CLOSED; if OPEN and not the probe, ignore the stale outcome.
- **(c) Stale failure while OPEN re-trips and silently extends `_opened_at`.**
  **Fix**: in `_on_failure`, if OPEN and not the probe, leave `_opened_at` alone.

**Tests** (`tests/test_resilience.py`, manual clock throughout):
- probe raises `asyncio.CancelledError` → a subsequent call after the reset timeout is still
  admitted (not wedged);
- threshold 2, three concurrent `execute`s via `gather` where two fail before the third resolves ok
  → breaker still OPEN;
- **also add the missing state-machine test** (independently flagged by the test audit):
  `test_half_open_admits_exactly_one_probe` — trip with threshold 1, advance clock past reset,
  park the probe on an `asyncio.Event`, assert a second call is rejected with
  "circuit breaker is open" *without running its handler*, then release the probe and assert CLOSED.

## C4. Idempotency middleware: get-then-put race runs concurrent duplicates twice — **high**

`packages/benzene-resilience/benzene/resilience/idempotency.py` (~95–107). Confirmed independently
by two audit tracks. `await store.get(key)` → `await next()` → `await store.put(...)` has await
boundaries between check and act: two concurrent deliveries of the same key both read `None` and
both run the handler — precisely the "charge the card once" scenario the module docstring promises
to prevent.

**Fix**: add an atomic reserve step. Extend the `IdempotencyStore` protocol with
`put_if_absent(key, value) -> bool` (in-memory impl: `dict.setdefault`, race-free because there is
no await inside; document that a Redis-backed store should use `SET NX`). Middleware flow:
`put_if_absent(key, IN_PROGRESS_MARKER)`; if False → read the stored value: a finished Result is
replayed (current behavior); an in-progress marker returns
`Result.failure(Status.CONFLICT, "duplicate delivery is already in flight")` (documented policy —
simplest correct behavior; redelivery will retry after the first completes). On completion,
overwrite the marker with the real result; when `should_remember` says no, delete the marker
(`finally`, so a raising handler doesn't leave the key reserved forever).

**Tests** (`tests/test_resilience.py`): two `gather`ed invocations with the same key and a handler
parked on `asyncio.Event` → handler ran exactly once, second delivery got the in-flight conflict;
handler raises → key not left reserved (a retry runs the handler again); plus the two untested
knobs flagged by the test audit: the `message-id` fallback header and a custom `remember_when`.

## C5. HTTP + gRPC senders can raise, breaking the "senders never raise" contract — **high**

`packages/benzene-http/benzene/http/client.py` (`stdlib_transport` ~103–117, `send_message` ~66–72),
`packages/benzene-grpc/benzene/grpc/client.py` (~37–45).

All eight broker/cloud senders map any send failure to `Result.failure(Status.SERVICE_UNAVAILABLE, ...)`
("never raising", per their docstrings). The HTTP default transport catches only
`urllib.error.HTTPError` — connection refused / DNS failure / timeout raise `URLError` straight out
of `await sender.send_message(...)`, bypassing `RetryingMessageSender` (which retries on Result
statuses, not exceptions). `GrpcMessageSender` catches only `grpc.RpcError` (e.g. a closed channel
raises `ValueError`).

**Fix**: in `HttpMessageSender.send_message`, wrap the transport call:
`except Exception as ex: return Result.failure(Status.SERVICE_UNAVAILABLE, str(ex))`, using
`Status.TIMEOUT` for `TimeoutError`. Keep the `KeyError` from `_resolve_url` raising (config error,
not transport). In `GrpcMessageSender.send_message`, add the same `except Exception` fallback after
the existing `grpc.RpcError` arm.

**Tests**: per sender, a transport/channel that raises (`URLError("refused")`, generic `Exception`)
→ `service-unavailable` Result, never an exception; `TimeoutError` → `timeout`.

## C6. RabbitMQ hardening: poison hot-loop, busy-poll, thread-unsafe shared channel — **medium ×3**

`packages/benzene-rabbitmq/benzene/rabbitmq/consumer.py` (`run_consumer_loop` ~116–131),
`packages/benzene-rabbitmq/benzene/rabbitmq/producer.py` (~60–96). One PR:

- **(a) Poison messages requeue forever in a hot loop.** A deterministic failure (malformed JSON →
  `bad-request`, unknown topic → `not-found`) is `basic_nack`ed with `requeue=True`, returns to the
  queue head, is immediately re-fetched, and spins at full speed with no retry cap or dead-letter
  path. **Fix**: nack with `requeue=False` for non-retryable statuses (reuse `DEFAULT_RETRYABLE`
  from `benzene.core.outbound` — anything not in it is final); keep requeue for transient statuses.
  Document that a DLX (dead-letter exchange) on the queue receives the dropped deliveries.
- **(b) Idle queue is busy-polled.** `basic_get` on an empty queue returns instantly and the loop
  `continue`s with no delay (unlike Kafka's `poll_timeout` / SQS's 20s long poll). **Fix**: add
  `idle_sleep: float = 1.0` and `await asyncio.sleep(idle_sleep)` when `method is None`.
- **(c) Producer shares one pika channel across `to_thread` workers, and connects on the event
  loop.** `pika.BlockingConnection`/channels are not thread-safe; concurrent `send_message` calls
  run `basic_publish` on separate OS threads against one channel → interleaved AMQP frames. The lazy
  `pika.BlockingConnection(...)` is also blocking network I/O on the loop thread. **Fix**: add
  `self._lock = asyncio.Lock()` held across client creation + publish, and move the lazy connect
  inside the threaded callable (mirror `KafkaMessageSender._publish`, which builds inside the
  thread).

**Tests** (`tests/test_rabbitmq.py`): bad-request delivery → `basic_nack(requeue=False)` and the
loop doesn't refetch it; transient failure → `requeue=True` preserved; empty-queue fake → loop
sleeps between gets (assert via a recording fake clock/sleep, not real time); producer fake channel
recording concurrent entry with a threading event → never >1 under `gather`; connection created in
the worker thread (spy on `to_thread` like `tests/test_aws_sqs_consumer.py`'s pin).

## C7. HTTP 204 responses are sent with a JSON body — protocol violation ⚠️ — **medium**

`packages/benzene-http/benzene/http/status.py` (~15–17: `UPDATED`/`DELETED` → 204),
`packages/benzene-http/benzene/http/app.py` (`__call__` ~227–241),
`packages/benzene-core/benzene/core/envelope.py` (`encode_response` ~103–109).

`Result.updated(payload)` / `Result.deleted(payload)` produce HTTP 204 *with* a non-empty body.
RFC 9110 forbids content with 204, and h11-based servers (uvicorn) raise `LocalProtocolError`
mid-response — the client sees a severed connection. (Also latent: reverse mapping sends 204 →
`deleted`, so `updated` never survives an HTTP hop.)

**Fix**: in the ASGI send path, when the mapped status code is 204 (or 304), send `b""` as the body
regardless of payload. Do **not** change the status mapping table (it is conformance-pinned).
Document on `Result.updated`/`Result.deleted` that a payload does not cross an HTTP hop (204 has no
body by protocol; other transports carry it). ⚠️ Re-run the conformance runner and say so in the PR.

**Test** (`tests/test_http.py`): handler returns `Result.updated({"x": 1})`; drive the ASGI app with
a recording `send`; assert status 204 with body `b""` — never 204 + bytes.

## C8. Mesh collector: unbounded event log + synchronous store save on the event loop — **medium**

`packages/benzene-mesh/benzene/mesh/collector.py` (`self._events` list ~124, append ~184,
`_persisted` → full `snapshot()` + `store.save()` after every ingest ~363–366),
`packages/benzene-mesh/benzene/mesh/store.py` (`save` is sync file/S3 I/O).

`_events` is append-only (unlike `QueueTraceExporter`'s capped deque): a long-lived collector's
memory, snapshot size, and every full-scan query grow forever, and each ingest re-serializes the
entire history through a synchronous S3 PUT / fsync **on the event loop**, blocking it.

**Fix**: (1) make `_events` a `collections.deque(maxlen=max_events)` with a constructor parameter
(default 10_000); keep `_span_owner` tolerant of evicted spans (lookups already use `.get`) and
rebuild it from retained events in `restore`; document the cap in `snapshot`'s docstring.
(2) run `self._store.save(...)` via `asyncio.to_thread` (make `_persisted` async and await it from
the ingest handlers). ⚠️ The collector conformance fixtures must stay green — the cap default is far
above any fixture's event count; state the re-run in the PR.

**Tests** (`tests/test_mesh_collector.py` or sibling): `max_events=3`, ingest 5 traces → snapshot
holds 3 and queries still answer; snapshot→restore round-trip rebuilds span ownership from the
retained window; a `to_thread` spy pins the save off the loop (same pattern as
`tests/test_egress_offloads_the_event_loop.py`).

## C9. RedisCache TTL edges: `px=0` (Redis error) and truncated fractional seconds — **low**

`packages/benzene-cache/benzene/cache/redis.py` (`set`, ~56–60). `ttl=0.0004` → `px=int(0.4)=0`,
which Redis rejects ("invalid expire time"); `ttl=1.9` → `ex=1`, silently halving the lifetime.

**Fix**: `px = max(1, math.ceil(ttl * 1000))` when `ttl < 1`, else `ex = math.ceil(ttl)` — round up,
never down/zero.

**Tests** (`tests/test_cache.py`): fake client asserts `px=1` for `ttl=0.0004`; `ex=2` for `ttl=1.9`.

# P1 — API, DX, and consistency

## D1. Optional-dependency policy: a missing SDK must raise a teaching ImportError, not become a Result — **high**

Sites: `packages/benzene-aws/benzene/aws/clients.py` (five `import boto3` sites),
`packages/benzene-azure/benzene/azure/clients.py` (~54, 62, 124, 208),
`packages/benzene-kafka/benzene/kafka/producer.py` (~51–56),
`packages/benzene-rabbitmq/benzene/rabbitmq/producer.py` (~60–68),
`packages/benzene-gcp/benzene/gcp/pubsub.py` (~65–70),
`packages/benzene-cache/benzene/cache/redis.py` (~24),
`packages/benzene-auth/benzene/auth/bearer.py` (~139),
`packages/benzene-mesh/benzene/mesh/inbox.py` (~47), `.../mesh/s3_artifacts.py` (~53),
`packages/benzene-mesh-fleet/benzene/mesh_fleet/discovery_adapters.py` (~45, 97, 150, 197).

Today the lazy `import boto3` (etc.) runs *inside* each sender's `try/except Exception` mapper, so a
deployment that forgot the extra never crashes — every publish quietly returns
`service-unavailable: "No module named 'boto3'"`, which retry middleware and circuit breakers then
hammer. The codebase already states the right philosophy in two places: `bearer.py` ("a missing
PyJWT is a deployment error, not a token outcome — surface it") and the grpc import guard, which
raises an ImportError naming the exact extra.

**Fix** (standardize on the grpc/auth pattern at every site):
- wrap each lazy import: `try: import boto3` / `except ImportError as exc: raise ImportError("<ClassOrFn> requires <dep> — install it with 'pip install <package>[<extra>]'") from exc`
  with the correct package[extra] per site (aws→`benzene-aws[boto3]`; azure per-class
  `[servicebus|storage|eventgrid]`; kafka→`benzene-kafka[kafka]`; rabbitmq→`benzene-rabbitmq[rabbitmq]`;
  gcp→`benzene-gcp[pubsub]`; cache→`benzene-cache[redis]`; auth→`benzene-auth[jwt]` (also mention
  "or inject your own decode callable"); mesh→`benzene-mesh[aws]`; mesh-fleet per-adapter
  `[aws|azure|kubernetes]`).
- in every `send_message`-style `except Exception` mapper, add `except ImportError: raise` *before*
  the generic arm (exactly the existing `bearer.py` shape) so the teaching error escapes.
- keep all imports lazy — no module may start crashing at import time (verified today: all 19
  import clean with zero optional deps; keep it that way).

**Tests**: one parametrized test that monkeypatches the relevant module out of `sys.modules`
(`monkeypatch.setitem(sys.modules, "boto3", None)`) per site-family and asserts the ImportError
message names the extra, and that it *propagates* out of `send_message` rather than becoming a
Result.

## D2. `HttpRouter` silently rebinds a topic to a different handler — **high**

`packages/benzene-http/benzene/http/routing.py` (`_register`, ~142–145). `Registry` raises
`DuplicateHandlerError` on a repeated `(topic, version)`; `HttpRouter._register` does
`self._definitions[key] = definition` — last write wins. Verified: two routes registering the same
topic with different handlers → **both** routes serve the second handler.

**Fix**: in `_register`, when the key exists and the stored `handler is not definition.handler`,
raise `benzene.core.DuplicateHandlerError` with:
"Route {method} {path} maps topic {topic!r} to a different handler than an earlier route. Two routes
may share a topic only when they share the handler (stack @http_endpoint, or register the same
function); otherwise give each handler its own topic." The same-handler-multiple-routes path must
keep working (documented stacked-decorator case; `add()` relies on it).

**Test** (`tests/test_http.py`): different-handler duplicate → raises; same-handler two routes →
still fine.

## D3. Bare `@validated` (no model) is accepted, then fails at runtime with a baffling error — **high**

## D4. Getting-started's first command cannot succeed until the PyPI publish — **high (docs)**

## D5. `not-found` for a versioned topic never mentions versions ⚠️ — **medium**

`packages/benzene-core/benzene/core/router.py` (~31–34); `registry.versions_of` already exists.
A wrongly-versioned message for a registered topic returns "No handler found for topic X" — the
developer stares at a topic that *is* registered; the version mismatch is invisible.

**Fix**: when the selector misses, look up `registry.versions_of(context.topic)`; if non-empty:
`Result.not_found(f"No handler for topic {context.topic!r} version {context.version or '(unversioned)'!r}; registered versions: {sorted(...)}. Send the version in the 'benzene-version' header, or register an unversioned handler.")`;
else keep the current message + " (no handlers registered for this topic)". Build the richer
message only *after* the selector (incl. `highest_version`) misses. ⚠️ No conformance fixture pins
router detail text (verified by grep), but re-run the runner and state it in the PR.

**Tests** (`tests/test_versioning.py` or `test_core_router.py`): wrong version → message lists
registered versions; unregistered topic → the plain message.
